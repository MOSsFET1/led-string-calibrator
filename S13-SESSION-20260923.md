1. **Batched multi-LED-off pairs (the big one).** The pair cost is dominated

## S13B (Sep 23, evening) — K-batched pairs with the #0 single-LED anchor

Operator directives: build the batched variant; K as a CFG parameter (no
reload to change); ALWAYS start with a single-LED #0 pair as the anchor.

- `CFG.holeBatch` (default 2, clamped 1–8) = LEDs off per pair; 1 = the
  original singles scheme. `CFG.holeAssignR` (default 20 px) = assignment
  radius. Both live-tunable via CFG= (no reload).
- Mechanism: holeMap (in-page, survives between runs; a reload clears it)
  holds every LED's last located position. Run shape:
  1. #0 single pair ALWAYS runs first. Its verdict must exist AND agree
     with holeMap[0] (≤ holeAssignR) — else the WHOLE run is singles
     (which rebuilds the map). First run after a reload: no map → singles.
  2. Batched runs turn off K consecutive LEDs per pair; each detected hole
     is assigned to the index whose map position is within holeAssignR;
     the group resolves ONLY if every index has exactly one hole and no
     hole is claimed twice. Anything else → that group re-runs as singles
     (correctness first; speed when confident).
  3. Batch-found lines carry `bK<n>`; fallbacks log
     `batch [i,j] ambiguous (N holes) -> singles fallback`.
- Detection/boxes/evidence unchanged (same thr/domK/area cap; same #i
  overlay). Expected: ~76 singles-equivalents per 150 px at K=2 → ~40–45 s
  (anchor + map-miss fallbacks add some singles back).
- Session flow after the S13B reload: run 1 = singles (map build, ~60 s);
  run 2+ = batched (~35–40 s expected). Console: same hole_session stages;
  watch the `hole batched run` / `hole singles run` gate line per run.

## S13E (Sep 23, night 2) — the dim-neighbour reflection fix (operator scheme)

Operator's mechanism: occasional reflection detections are the lit die
clipping in the sensor — the die and its reflection read equally bright,
so the impostor's dominance can win. Fix under test: while scanning LED x,
DIM LED x+1 (K > 1: dim every off-LED's +1 neighbour) to HALF brightness —
attacks the brightest clip source adjacent to each hole while the field
stays bright for AE (two LEDs of 150 changing <1% scene luma: still no AE
pump). Implementation:
- Firmware `frame` paint grammar gains "H" = half-bright white (b/2) —
  the dim fraction is FIRMWARE-side by design (the page sends a symbolic
  slot; the box computes the level, so a CFG fraction later only touches
  the firmware, not the message size).
- Page CFG.holeDimNext (0/1, live) + CFG.holeDimFrac (declared; the page
  records it but the slot is firmware-computed at holeB/2 for now).
  Singles + batch paths dim; an off-slot's own null wins over its dim.
- Expected side-effect: the dimmed neighbour leaves a HALF-DEPTH hole one
  pitch from each true hole — outside holeAssignR for most of the string,
  but tight-pitch neighbours may fall inside and add fallbacks. The A/B
  judges on: fallback rate, impostor accepts (offline), foundN.
- A/B protocol (after reload): E0 dim=off ×2 → E1 dim=on ×2 → compare
  fallback heads + per-run peak/d10 stats + offline re-diff. Decision by
  the standing rules (set inside measured gaps; drop a no-effect lever).
